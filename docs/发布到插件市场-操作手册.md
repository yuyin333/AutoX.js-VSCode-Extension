# 发布到插件市场 · 操作手册

> 适用版本：`autox-js-vsce-ai` 2.2.x　｜　渠道：VS Code Marketplace + Open VSX
> 认证方式：**OIDC 信任发布**（不用 PAT，因为 Azure DevOps 全局 PAT 将于 **2026-12-01 退役**）
> 现状（2026-10-22 实测）：扩展 id 定为 `autoxai.autox-js-vsce-ai`；publisher `autoxai` 尚未被占用

---

## 0. 全流程一览

```
一次性准备                                  每次发版
├─ 1. Microsoft 账号 + 建 publisher autoxai   ├─ 1. 改 package.json 的 version
├─ 2. 配 trusted publishing（仓库+workflow）  ├─ 2. commit + push
├─ 3. Eclipse 账号 + 签协议 + Open VSX token  ├─ 3. git tag vX.Y.Z && git push origin vX.Y.Z
├─ 4. 建 Open VSX 命名空间 autoxai            └─ 4. 等两个 Actions 跑完（约 3~5 分钟）
└─ 5. GitHub 仓库 Secrets 加 OVSX_PAT
```

首次大约 40 分钟（大部分在注册账号），之后每次发版 3 分钟。

---

## 1. 一次性准备

### 1.1 创建 Marketplace Publisher

1. 打开 <https://marketplace.visualstudio.com/manage>，用 Microsoft 账号登录
2. 点 **Create publisher**
3. 填写：
   - **ID**：`autoxai`
   - **Name**：随便填（会显示在扩展页的"发布者"处，例如 `Autox.js Ai`）
4. 创建后**记下 ID** —— 它必须和 `package.json` 里的 `publisher` 完全一致

> ⚠️ Publisher ID **创建后永久不可修改**，会出现在扩展 URL 里：
> `marketplace.visualstudio.com/items?itemName=autoxai.autox-js-vsce-ai`

### 1.2 配置 OIDC 信任发布（关键，不配就发不出去）

在 publisher 管理页 → 选中 `autoxai` → **Trusted publishing**（部分界面叫 *Trusted publishers*）→ 添加策略：

| 字段 | 填什么 |
|---|---|
| Repository | `yuyin333/AutoX.js-VSCode-Extension` |
| Workflow | `publish.yml` |

含义：允许这个仓库的这个 workflow 代表 `autoxai` 发布。
不配的话，Actions 里的 token 交换会报 `no trust policy matches` / `trusted publishing not supported`。

### 1.3 Open VSX（VSCodium 等衍生版用）

1. 注册 Eclipse 账号：<https://accounts.eclipse.org/user/register>
   **GitHub Username 一栏必须填 `yuyin333`** —— 要和后面登录 open-vsx.org 用的 GitHub 账号一致
2. 登录 <https://open-vsx.org> → 头像 → **Settings** → **Log in with Eclipse** → 授权
3. 同一页面点 **Show Publisher Agreement** → 读到底 → **Agree**
4. 头像 → Settings → **Access Tokens** → **Generate New Token** → 复制（只显示一次）
5. **建命名空间**（必须等于 `package.json` 的 `publisher`）：

```bash
npx ovsx create-namespace autoxai -p <你的TOKEN>
```

> 创建命名空间 ≠ 认证所有者。想让扩展显示"verified"，还要按
> <https://github.com/eclipse/openvsx/wiki/Namespace-Access> 认领命名空间。

### 1.4 GitHub 仓库 Secrets

仓库 → Settings → Secrets and variables → Actions → **New repository secret**：

| Name | Value |
|---|---|
| `OVSX_PAT` | 1.3 第 4 步生成的 token |

（Marketplace 那条走 OIDC，**不需要**任何 secret。）

## 2. 代码侧准备（已在本仓库改好）

| 文件 | 改动 | 为什么必须 |
|---|---|---|
| `.vscodeignore` | 增加 `*.vsix`、`.git/**`、`docs/**`、`package-lock.json`；删掉死规则 `!src/document` | 不加的话 `vsce package` 会把 8 个历史 vsix（28.3MB）和 `.git`（含 commit 邮箱）打进包 |
| `package.json` | `license` → `GPL-2.0-only`；删 `__npminstall_done`；`categories` 加 `Programming Languages` | `GPL-2.0` 是废弃 SPDX 写法；`Other` 分类几乎搜不到 |
| `README.md` / `CHANGELOG.md` | 把 `[LICENSE.md](LICENSE.md)` 改成纯文本 | **vsce 4 遇到"相对链接 + 无 repository"会直接 ERROR 退出**（不是警告），实测已修 |
| `.github/workflows/publish.yml` | Marketplace OIDC 发布 | — |
| `.github/workflows/publish-openvsx.yml` | Open VSX 发布 | — |

发布前确认：

```bash
cd "E:/编程资料/autojs软件/AutoX-VSCode-Extension"
npm ci                 # 首次或依赖变动后
npm run compile        # 产出 out/*.js（CI 里由 vscode:prepublish 自动跑）
git status             # 应当只有上面这些改动的提交
git push origin master
```

## 3. 本地先验一遍（强烈建议，别把第一次交给 CI）

```bash
cd "E:/编程资料/autojs软件/AutoX-VSCode-Extension"

# 3.1 看会打进包的文件清单（注意：ls 不支持 --allow-missing-repository，加了会报 unknown option）
npx --yes @vscode/vsce@4.0.0 ls

# 3.2 真打一个包（dist 目录要先建，vsce 不会自动创建）
mkdir -p dist
npx --yes @vscode/vsce@4.0.0 package --allow-missing-repository -o dist/publish.vsix
```

**实测结果（2026-10-22，vsce 4.0.0）：**

| 检查点 | 结果 |
|---|---|
| 包体积 | **3.56 MB / 2548 files**（修复前会把 8 个历史 vsix 打进去，约 29 MB） |
| `vsce ls` 输出 | **不含** `.git/`、`*.vsix`、`src/`、`docs/`、`.github/`、`package-lock.json` |
| 含 | `out/*.js`(7)、`node_modules/`(2529 files, 10.17MB 解压)、readme.md/changelog.md、LICENSE.md、logo.png、snippets、assets |
| manifest | `Id="autox-js-vsce-ai" Publisher="autoxai" Version="2.2.2"`，三者与 package.json 一致 |

再本机装一下，确认不是"能打包但不能用"：

```bash
code --install-extension dist/publish.vsix --force
# 重启 VS Code → 命令面板搜 "Autox.js: 开启服务" 能出现，扩展面板能看到 Autox.js-VSCodeExt-Ai
```

> `--allow-missing-repository` 是必须的：`package.json` 里没有 `repository` 字段，
> 不加这个开关 vsce 会交互式问 `Do you want to continue? [y/N]`，CI 里会卡住直到超时。

## 5. 后续更新 / 回滚

### 发新版

改 `package.json` 的 `version`（并同步 CHANGELOG）→ commit → 打 tag：

```bash
git tag v2.2.3 && git push origin v2.2.3
```

> tag 必须和 `version` 一致，否则两个 workflow 打出来的包和 tag 对不上（建议自行加一步校验）。

### 下架（可逆）

管理页 → 该扩展 → **More Actions** → **Unpublish**。用户装不了，但统计保留。

### 删除（不可逆！）

```bash
npx @vscode/vsce unpublish autoxai.autox-js-vsce-ai
```

**扩展名会被永久占用，连你自己也不能再用同一个名字重新发布。**

### 删某个版本

管理页 → Reports → **Manage** 标签 → Delete this version（不能删最新版，删掉后该版本号不可复用）。

## 6. 报错对照表

| 报错 | 原因 | 解法 |
|---|---|---|
| `401 Unauthorized` / `403 Forbidden` | publisher 没建，或 OIDC 策略没配 | 回到 1.1 / 1.2 |
| `trusted publishing not supported` / `no trust policy matches` | 策略里的仓库/文件名和实际不一致 | 检查 1.2 的 Repository 与 Workflow 拼写 |
| `A 'repository' field is missing...` | 缺 repository 又没加开关 | 加 `--allow-missing-repository` |
| `ERROR The extension 'xxx' already exists` | 同 publisher 下重名 | 改 `name` |
| `Extension entrypoint(s) missing` | `out/` 没编译 | 本地 `npm run compile`；CI 由 `vscode:prepublish` 自动跑 |
| `Make sure to edit the README.md file before you package` | README 还是模板 | 本项目已改过，不会触发 |
| `EPUBLISHCONFLICT` / 版本已存在 | 同版本重复发布 | 升 `version` 再发 |
| `ovsx` 报 `Namespace not found` | 命名空间没建或与 publisher 不一致 | 执行 1.3 第 5 步 |
| Actions 卡住不动、无输出 | 少了 `--allow-missing-repository`，vsce 在等交互输入 | 见上 |
| `Couldn't detect the repository ... The link 'LICENSE.md' will be broken` | README/CHANGELOG 里有相对链接但没有 repository | 把 `[LICENSE.md](LICENSE.md)` 改成纯文本（已修） |
| `ENOENT ... dist\publish.vsix` | 输出目录不存在 | 先 `mkdir -p dist` |
| `error: unknown option '--allow-missing-repository'` | 该参数只属于 `package`/`publish`，`ls` 不支持 | `ls` 别加这个参数 |

### 如果 OIDC 彻底走不通

有报告称部分账号的 `--oidc` 会报 `trusted publishing not supported`，此时两条退路：

1. **临时 PAT**（只能用到 2026-12-01）：
   Azure DevOps → User settings → Personal access tokens → New Token →
   Organization 选 **All accessible organizations**，Scope 勾 **Marketplace → Manage**；
   然后 `npx @vscode/vsce publish --pat <PAT> --allow-missing-repository`
2. **Entra ID**：`vsce publish --azure-credential`，需要 Azure 订阅 + 用户分配托管身份 +
   联合凭据 + 把该身份加成 publisher 的 Contributor（配置明显更重，但长期有效）。

## 7. 已知风险与合规（发布前请确认你接受）

### 7.1 GPL-2.0 与源码获取

本插件是 GPL-2.0 代码的衍生作品，分发时必须让对方能拿到源码。
当前处理方式是"不打包 `src/`、不填 `repository`"——**严格说这是不合规的**。
事实层面你的 GitHub 仓库 `yuyin333/AutoX.js-VSCode-Extension` 是 public，源码可被获取，但这不等于履行了 GPL 的"提供源码"义务。

最低成本兜底（建议加，一行）：在 README 里加一句

> 本扩展遵循 GPL-2.0。完整源码可按请求提供（书面请求即可）。

这句话对应 GPLv2 §3(b) 的 written offer，比完全沉默强得多。

### 7.2 MCP 端口访问控制（2.2.3 已修）

原问题：服务只监听 `127.0.0.1:18789`，但浏览器里任意网页都能
`fetch('http://127.0.0.1:18789/mcp', {mode:'no-cors', headers:{'Content-Type':'text/plain'}})`
—— `text/plain` 绕过预检、服务端照单全收 JSON，于是网页可以调 `device_run_code` 在用户手机上执行任意 JS；
再加上 `Access-Control-Allow-Origin: *`，网页还能读到响应。

2.2.3 起在路由前统一拦截，**不需要账号体系、不需要客户端改配置**：

| 层 | 规则 | 作用 |
|---|---|---|
| Host | 必须是 `127.0.0.1` / `localhost` / `[::1]` | 挡 DNS rebinding |
| Origin | 带 `Origin` 头一律 403 | 本地 MCP 客户端不发 Origin，发的一定是浏览器 |
| CORS | 不再发 `Access-Control-Allow-Origin` | 网页读不到响应 |
| Token（可选） | `autoxAi.mcpToken` 非空时要求 Bearer / `?token=` | 共享机器再上一层保险 |

默认零配置，现有 `{"url":"http://127.0.0.1:18789/mcp"}` 照旧可用。

### 7.3 与上游同名/仿冒投诉

显示名 `Autox.js-VSCodeExt-Ai` 与原版 `Auto.js-Autox.js-VSCodeExt` 高度相似。
目前 README/CHANGELOG 保留了"衍生作品 + GPL-2.0"声明，这是最有力的抗辩。
若上游投诉，最坏结果是要求改名或下架。

### 7.4 账号可见性

Publisher 背后的 Microsoft 账号、Open VSX 背后的 GitHub/Eclipse 账号都是实名可查的。
Publisher **ID 和显示名**可以中性化，但平台侧一定知道是谁发布的。这和你之前"不留下痕迹"的目标只能做到这一步。
